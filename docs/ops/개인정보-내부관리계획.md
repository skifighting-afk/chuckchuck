# 개인정보 내부 관리계획 (초안)

> 개인정보의 안전성 확보조치 기준 제4조에 따른 내부 관리계획. 법률 검토 전 초안이며, 사업자·보호책임자를 정하면 이름을 채우고 대표가 승인한다.

## 1. 책임자와 담당
- 개인정보 보호책임자: (대표 또는 지정자 — `lib/operator.ts` privacyOfficer와 같게)
- 취급자: 운영자 계정(HQ_ADMIN_EMAIL) 1명. 늘면 이 표에 이름·권한·지정일을 적는다.

## 2. 접근 권한
- 운영자 화면(/admin)은 가게별 집계만 본다. 직원 개인정보·계약서·급여 상세는 보지 않는다.
- 운영자가 가게 정보를 열면 기록을 1년 남긴다(본사 열람 기록).
- 서버 비밀값은 GitHub Secrets·Supabase Secrets에만 둔다. 채팅·문서·커밋에 쓰지 않는다.
- 권한을 주거나 회수하면 날짜와 사유를 이 문서 아래 기록표에 남긴다.

## 3. 접속 기록
- 로그인 성공·실패(90일), 가게 변경 이력(최근 1,000건), 개인정보 열람 기록, 운영자 열람 기록(1년).
- 매월 첫 영업일에 운영자 접속·열람 기록을 확인하고, 이상하면 침해사고 대응 절차를 따른다.

## 4. 암호화
- 비밀번호: Supabase Auth 해시. 2단계 인증 비상 코드·세션·토큰·API 키는 해시만 저장.
- 전송: 모든 화면·서버 통신 HTTPS. 주간 백업은 암호화해 보관.

## 5. 보안 점검
- 배포마다 자동 점검(권한·출처·신원 헤더 위조·접근성). 분기마다 의존성 업데이트와 취약점 확인.
- 취약점 신고: /.well-known/security.txt → 문의하기(종류: 신고).

## 6. 교육
- 취급자는 연 1회 개인정보 보호 교육(개인정보보호위원회 무료 온라인 교육)을 듣고 날짜를 남긴다.

## 7. 위탁·국외 이전
- 처리방침 5·6항과 같게 유지한다. 업체를 바꾸면 처리방침을 먼저 고친다.
