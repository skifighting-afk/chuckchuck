# 척척사장봇 작업 지시서 (100개)

너는 척척사장봇 저장소(skifighting-afk/chuckchuck, 브랜치 main)를 맡은 개발자다. 아래 100개 작업을 순서대로 끝까지 진행해.

## 먼저 읽을 것
- README.md, docs/handoff/HANDOFF-CLAUDE.md
- 구조: 화면 React+TS(app/*.tsx) → GitHub Pages / 서버는 app/worker.ts를 Supabase Edge Function(supabase/functions/api)으로 실행 / DB는 Supabase Postgres(supabase/migrations) / 로그인은 Supabase Auth / 급여 규칙은 lib/pay-rules.ts
- 테스트: npm test (Postgres 필요, scripts/test-db.mjs), npm run check:function

## 진행 규칙
1. 단계 순서(1단계 → 2단계 → 3단계)대로, 단계 안에서는 적힌 순서대로 한다. 앞 작업이 뒤 작업의 전제면 그 순서를 지킨다.
2. 작업 하나 = 커밋 하나. 커밋 메시지 첫 줄에 "작업 NNN: 제목"을 쓴다.
3. 기능을 바꾸면 scripts/check-*.mjs에 점검을 추가하고, npm run check · npm test가 통과한 뒤에만 커밋한다.
4. main에 푸시한 뒤 GitHub Actions 결과(ci-status 브랜치의 status.json과 로그)를 확인하고, 실패하면 다음 작업으로 넘어가기 전에 고친다.
5. 법·요율·세액 기준은 최신 공식 자료(고용노동부, 국세청, 보건복지부, 국민연금공단, 법제처)로 확인하고, 코드 주석이나 docs에 출처와 기준일을 남긴다. 추측으로 숫자를 넣지 않는다.
6. 확인되지 않은 기능을 화면·홈페이지에 "제공"이라고 쓰지 않는다. 가짜 후기·수치·고객 로고를 만들지 않는다.
7. "준비물"이 필요한 작업에서 그 값(API 키, 계정, 사업자 정보 등)이 없으면: 값 없이 할 수 있는 부분(코드, 테스트용 가짜 응답, 설정 자리, 문서)까지 만들고, 필요한 값을 docs/WAITING.md에 적은 뒤 다음 작업으로 넘어간다. 비밀값은 코드나 커밋에 절대 넣지 않는다.
8. 운영 DB에 영향을 주는 마이그레이션은 되돌리는 SQL을 함께 만들고, 기존 데이터 이전을 테스트한다.
9. 10개 작업마다 docs/PROGRESS.md에 끝낸 작업, 남은 작업, 막힌 작업(이유)을 갱신해 커밋한다.
10. 되돌릴 수 없고 판단이 갈리는 결정(데이터 삭제, 가격·약관 확정, 외부 서비스 계약)은 직접 정하지 말고 docs/DECISIONS.md에 선택지와 추천을 적고 넘어간다.

## 1단계 · 출시 전 (실제 고객을 받기 전에 끝낼 것)

### 배포·인프라

**작업 001 · 첫 배포**  _(준비물: GitHub 저장소·Supabase 비밀값)_
supabase 브랜치를 main으로 합쳐 새 GitHub 저장소에 올리고, 첫 GitHub Actions 실행 결과를 ci-status 브랜치에서 확인해 실패한 단계를 고쳐 줘. 타입 검사·테스트·Pages·Supabase 배포가 모두 성공할 때까지.

**작업 002 · 로컬 개발 환경**
npm run dev 하나로 Supabase 로컬 스택(supabase start), 화면 빌드 감시, 서버 함수 실행이 같이 뜨게 만들고 README에 순서를 적어 줘.

**작업 004 · 배포 후 실제 점검**
배포가 끝나면 실제 주소에서 Playwright로 가입 → 가게 만들기 → 로그아웃 → 다시 로그인을 돌리고, 실패하면 ci-status에 기록하고 Actions를 실패로 표시해 줘. 점검용 계정은 끝나고 지워.

**작업 005 · 되돌리기 절차**
소스와 DB 마이그레이션을 이전 버전으로 되돌리는 절차를 docs/rollback.md에 쓰고, 마이그레이션마다 되돌리는 SQL을 함께 두는 규칙을 만들어 줘.

**작업 006 · DB 백업**
매일 새벽 GitHub Actions 예약 작업으로 Supabase DB를 pg_dump 하고 암호화해서 7일치를 보관해 줘. 복구 연습 절차도 문서로.

**작업 007 · 오류 수집**
서버 함수 오류를 Supabase 로그(또는 Sentry)로 모으고, 사용자에게는 오류 번호만 보여 줘서 문의할 때 찾을 수 있게 해 줘. 개인정보는 로그에 남기지 마.

일급·월급 직원의 통상시급 환산과 주휴 포함 여부 설정을 만들어 연장·야간 가산이 계산되게 해 줘. 지금은 시급 직원만 자동.

**작업 028 · 5명 이상 자동 판단**
최근 1개월 출퇴근 기록으로 상시근로자 수(연인원 ÷ 가동일수)를 계산해 "5명 이상 설정" 변경을 제안해 줘.

**작업 029 · 연차 자동 발생**
연차유급휴가 자동 발생(1년 미만 월 1일, 1년 이상 15일 + 가산), 사용·잔여, 미사용 수당 계산을 5명 이상 사업장에 붙여 줘.

**작업 033 · 사장님 부담 4대보험**
사장님 부담분 4대보험(국민연금, 건강, 장기요양, 고용, 산재)을 계산해 인건비 보고서에 넣어 줘. 산재·고용 사업주 요율은 업종별 입력.

**작업 034 · 중도 입·퇴사 일할**
월급 직원이 달 중간에 입사·퇴사하면 일할 계산하고 계산식을 명세서에 표시해 줘.

### 근로계약

**작업 038 · 계약서 PDF**
계약서·명세서를 지금의 PNG 대신 PDF로도 내려받게 해 줘. 화면에서 만들고 한글 글꼴 포함.

**작업 040 · 변경 계약**
시급 인상처럼 근로조건이 바뀌면 변경 계약서 초안을 자동으로 만들고 다시 서명받는 흐름을 만들어 줘.

**작업 042 · 계약서 메일 실제 확인**  _(준비물: Resend 계정·발신 도메인)_
Resend를 연결한 뒤 계약서 사본 메일이 실제로 발송·수신되는지 확인하고, 실패 상태가 화면에 정확히 남는지 테스트해 줘.

**작업 043 · 표준서식 최신화**
고용노동부 표준 근로계약서 최신 서식과 lib/contract-template.ts를 비교해 다른 점을 고치고 출처를 남겨 줘.

### 출퇴근·근무표

**작업 044 · QR 대리출근 방지**
매장 QR을 30초마다 바뀌는 시간 기반 코드로 바꿔서 사진으로 찍어 두고 쓰기 어렵게 해 줘. 화면에 남은 시간 표시.

**작업 046 · 지각·미출근 표시**
근무표와 실제 출퇴근을 비교해 지각·조퇴·미출근을 표시해 줘.

**작업 051 · 퇴근 누락 알림**
퇴근을 안 찍은 기록을 다음 날 자동으로 찾아 직원에게 정정 요청을 안내해 줘.

### 직원·계정

**작업 055 · 매니저 권한 이력**
매니저 권한을 주고 회수한 기록을 남기고, 회수가 즉시 반영되는지 테스트를 보강해 줘.

**작업 058 · 초대 링크 관리**
직원 초대 링크의 만료·재발급·취소 화면을 정리해 줘.

### 결제·요금

**작업 062 · 결제 연동**  _(준비물: 토스페이먼츠 가맹)_
토스페이먼츠 결제위젯을 테스트 키로 붙여 줘: 요금제 선택 → 결제 → 서버 함수에서 승인 → 이용권 반영. 금액은 서버에서만 계산.

**작업 063 · 정기결제**  _(준비물: 정기결제 계약)_
정기결제(빌링키) 등록과 매월 자동 청구 예약 작업, 실패 시 재시도와 안내를 만들어 줘.

**작업 064 · 결제 내역**
결제 내역과 영수증 화면을 만들어 줘.

**작업 065 · 체험 종료 안내**
14일 체험 종료 7일·1일 전 안내를 넣고, 유료 전환은 사장님이 직접 동의할 때만 되게 해 줘.

**작업 066 · 가격 변경 고지**
가격 인상·약관 변경을 30일 전에 알리고 동의 기록을 남기는 기능을 만들어 줘.

**작업 067 · 환불 계산**
중도 해지 환불 금액(일할) 계산과 환불 서버 함수를 만들어 줘.

**작업 069 · 세금계산서 정보**
고객 사업자 정보(세금계산서용) 입력란과 발행 요청 기록을 만들어 줘.

### 개인정보·보안

**작업 073 · 본사 열람 기록**
본사 계정이 고객 가게 데이터를 볼 때마다 기록을 남기고 본사 화면에서 볼 수 있게 해 줘.

**작업 075 · 취약점 점검**
Dependabot과 npm audit 워크플로를 추가해 줘.

**작업 078 · 요청 제한 확대**
로그인 말고도 모든 서버 경로에 IP·계정별 요청 제한을 붙여 줘.

### 품질·테스트

**작업 081 · 데이터 구조 나누기**
매장 데이터 한 덩어리(JSON) 구조를 직원·출퇴근·근무표 테이블로 나누는 단계별 계획을 쓰고 1단계를 실행해 줘.

**작업 082 · 응답 속도**
서버 함수 응답 시간을 재고 느린 쿼리에 인덱스를 추가해 줘. 전후 수치를 남겨.

**작업 084 · 글씨 크게 보기**
앱에도 "글씨 크게 보기" 설정을 넣어 줘. 나이 드신 사장님용.

**작업 086 · 빈 화면·로딩**
처음 쓰는 가게의 빈 화면, 로딩, 오류 상태를 화면마다 정리해 줘.

**작업 088 · 커버리지**
테스트 커버리지를 재고 급여·계약 모듈을 90% 이상으로 올려 줘.

**작업 089 · 모바일 화면 비교**
390px 폭에서 모든 화면을 캡처해 이전 버전과 비교하는 테스트를 만들어 줘.

### 알림·편의

**작업 091 · 앱 설치(PWA)**
manifest, 서비스워커, 홈 화면 설치 안내를 넣어 줘(+EV의 sw.js 참고).

**작업 096 · 오늘 할 일**
사장님 홈에 오늘 할 일(승인 대기, 미서명 계약, 퇴근 누락, 보낼 명세서)을 모아 보여 줘.

**작업 097 · 월말 마감 체크리스트**
급여 마감 전에 확인할 것(퇴근 누락, 정정 대기, 최저시급, 보험 상태)을 한 화면에 모아 줘.

**작업 099 · +EV와 엔진 공유**  _(준비물: plus-ev 저장소)_
lib/pay-rules.ts를 두 앱이 같이 쓰는 모듈로 분리하고, +EV 엔진의 장기요양 요율(12.95%→13.14%)과 5명 미만 가산수당 문제를 고쳐 줘.

## 3단계 · 성장

### 배포·인프라

**작업 010 · 첫 로딩 줄이기**
화면 묶음 크기를 재고, 본사·계약서·급여 화면을 필요할 때 불러오도록 나눠서 휴대폰 첫 화면 로딩을 줄여 줘. 전후 크기를 표로.

### 급여·명세서

**작업 031 · 계산 근거 펼쳐보기**
명세서의 각 줄을 누르면 그 금액에 들어간 출퇴근 기록과 계산식이 보이게 해 줘.

**작업 032 · 인건비 시뮬레이터**
시급과 근무 패턴을 넣으면 월 예상 인건비(사장님 부담 4대보험 포함)를 보여 주는 계산기를 만들어 줘.

**작업 035 · 지급일 경고**
급여 확정 때 지급일이 주말·공휴일이면 알려 줘.

### 근로계약

**작업 039 · 손서명**
서명 단계에 휴대폰 손서명(캔버스)을 추가하고 서명 이미지를 문서 스냅샷과 함께 보관해 줘.

**작업 041 · 기간제 만료 알림**
기간제 계약 만료 30일 전에 사장님 홈과 메일로 알려 줘.

### 출퇴근·근무표

**작업 048 · 근무표 복사·반복**
지난주 근무표 복사와 요일별 반복 템플릿을 만들어 줘(+EV의 shift_templates 참고).

**작업 049 · 대타·교대**
직원끼리 대타·교대를 요청하고 사장님이 승인하는 흐름을 만들어 줘.

**작업 050 · 근무 가능 시간**
직원이 근무 가능한 시간을 내고, 그걸로 근무표 초안을 자동으로 짜 주는 기능을 만들어 줘.

**작업 053 · 근무표 인쇄**
근무표를 A4 가로로 인쇄하기 좋은 화면을 만들어 줘.

### 직원·계정

**작업 054 · 직원 일괄 등록**
엑셀에서 복사한 표를 붙여 넣으면 직원 여러 명을 한 번에 등록하게 해 줘. 미리보기와 오류 줄 표시.

**작업 057 · 대표 변경**
가게 소유 사장님 계정을 다른 계정으로 넘기는 흐름(양쪽 확인)을 만들어 줘.

**작업 060 · 로그인 기기 관리**
로그인한 기기 목록과 전체 로그아웃 버튼을 만들어 줘.

### 결제·요금

**작업 068 · 매장 수 변경**
여러매장 요금제에서 매장 수를 바꾸면 차액을 계산해 보여 줘.

### 개인정보·보안

**작업 079 · 연락처 가리기**
직원 목록에서 연락처·주소를 가리고 눌렀을 때만 보이게 해 줘.

### 품질·테스트

**작업 087 · 타입 정리**
서버 코드부터 any를 줄이고 strict 경고를 정리해 줘.

### 알림·편의

**작업 092 · 웹 푸시**
명세서 도착, 계약 서명 요청, 정정 승인 결과를 웹 푸시로 알려 줘.

**작업 093 · 알림톡 준비**  _(준비물: 카카오 비즈 채널)_
카카오 알림톡 템플릿 문구 초안과 발송 서버 함수 뼈대를 만들어 줘(실제 발송은 비즈 채널 승인 후).

**작업 095 · 공지 읽음 확인**
매장 공지를 직원이 읽었는지 사장님이 볼 수 있게 해 줘.

**작업 100 · 도움말**
자주 묻는 질문 30개 도움말 페이지와 화면별 "이게 뭐예요?" 안내를 만들어 줘.
