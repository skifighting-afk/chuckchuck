# 개인정보 유출 사고 대응 절차 (작업 076)

> 법률 검토 전 초안. 근거: 개인정보 보호법 제34조(유출 등의 통지·신고), 같은 법 시행령 제39조·제40조.
> 시행령 기준(2023.9.15 개정): 유출을 **알게 된 때부터 72시간 이내**에 정보주체에게 통지하고,
> 1천 명 이상이거나 민감정보·고유식별정보가 포함되거나 외부 불법 접근으로 유출된 경우 72시간 이내에
> 개인정보보호위원회 또는 한국인터넷진흥원(KISA)에 신고한다. 정확한 요건은 신고 전에 최신 법령으로 다시 확인한다.

## 1. 알게 된 즉시 (첫 1시간)
1. 시각을 기록한다. 72시간은 이 시각부터 센다.
2. 피해가 커지지 않게 막는다.
   - 의심되는 토큰·키 폐기: Supabase 액세스 토큰(대시보드 Account → Access Tokens), DB 비밀번호 재설정(Project Settings → Database), service_role 키 재발급(Project Settings → API).
   - GitHub 저장소 비밀값(SUPABASE_ACCESS_TOKEN, SUPABASE_DB_PASSWORD) 교체.
   - 필요하면 서버 함수 중지: `supabase functions delete api` 대신 Supabase 대시보드에서 함수 비활성화, 또는 화면에 점검 안내 배포.
3. 증거를 남긴다: Supabase 로그(Logs → Edge Functions, Auth, Postgres), GitHub Actions 기록, 관련 화면 캡처. 지우거나 덮어쓰지 않는다.

## 2. 범위 파악 (24시간 안)
- 어떤 정보가: `docs/privacy-inventory.md` 목록 기준으로 표시
- 몇 명·몇 가게: DB에서 영향받은 `stores.owner`, `app_users` 수
- 어떻게: 원인(키 노출, 권한 버그, 외부 공격 등)과 기간
- 민감정보(건강정보가 담긴 휴가 증빙 등) 포함 여부

## 3. 통지·신고 (72시간 안)
- **정보주체 통지**(이메일·앱 공지): 유출된 항목, 시점과 경위, 피해를 줄이려고 정보주체가 할 수 있는 방법(비밀번호 변경 등), 우리가 한 조치, 피해 신고·상담 창구.
- 직원 개인정보는 가게(사장님)가 처리자이므로, **해당 사장님에게 먼저 알리고** 통지에 협조한다(처리위탁 조항, 작업 017).
- 신고 대상이면 개인정보보호위원회·KISA에 신고한다. 72시간 안에 다 확인하지 못했으면 확인된 내용으로 먼저 신고하고 추가로 보완한다.

## 4. 복구와 재발 방지
- 원인 수정 → 테스트 추가(`scripts/check-*.mjs`) → 배포 → ci-status 확인
- 이 문서와 `docs/privacy-inventory.md` 갱신, 사고 기록(일시, 범위, 조치, 통지·신고 내역)을 `docs/incidents/YYYY-MM-DD.md`로 남김
