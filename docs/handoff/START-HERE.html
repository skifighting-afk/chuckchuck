3. 개발자 시작 절차
Node.js >=22.13.0 필요. app-v23에서 npm ci → npm run build → npm run check → npm test.
실제 빌드는 scripts/portable-build.mjs가 app/client.tsx와 app/worker.ts를 dist/client 및 dist/server로 만든다.
package.json의 npm run dev는 구형 preview.mjs를 사용한다. 인증/계약용 전체 마이그레이션이 없고 local-owner 인증을 주입하므로 운영과 같은 로그인 검증용으로 쓰지 않는다.
Wrangler 로컬 실행은 npm run build 후 npm run start. 사전에 로컬 D1에 drizzle/0000~0003 SQL을 순서대로 적용해야 한다. 0004는 미완성 수정본용이다. 프로덕션 DB에는 검토 없이 적용하지 않는다.
dist/server/wrangler.json의 DB ID는 0으로 채운 플레이스홀더다. 실제 배포는 Sites 프로젝트 DB 바인딩을 사용한다.
DB 데이터와 비밀키는 이 묶음에 없다. 이 ZIP만으로 운영 고객 데이터까지 복제되지 않는다.
소스 수정 후 검증 → 동일 Sites 프로젝트의 소스 저장소에 정확한 커밋 push → 그 커밋으로 버전 저장 → 배포 → 성공 상태 확인. 새 사이트로 임의 재생성하지 않는다.
되돌릴 기준은 위 v23. DB 마이그레이션 되돌리기는 소스 롤백과 별도로 검토한다.

7. 접근 권한 인계
Readdy 편집은 해당 프로젝트의 초대 기능 사용. 화면에서 협업자가 소유자의 구독 크레딧을 쓴다고 안내한다. 보기 전용 링크와 편집 권한을 구분한다.
Sites 앱 방문 권한은 개발 편집 권한과 다르다. 현재 앱은 public이므로 화면 열기만을 위해 별도 방문자 초대가 필요하지 않다.
Sites 편집자 권한은 워크스페이스 계정으로 확인해 추가해야 하며 외부 방문자 이메일 등록으로 대체할 수 없다.
대표 계정 비밀번호를 전달하는 방식 대신 받는 계정에 필요한 권한을 부여한다. 소유권은 현재 소유자에게 유지한다.
확인 순서: 다른 PC /demo 열기 → 올바른 계정의 Readdy 프로젝트 확인 → 편집 권한 확인 → ZIP 압축 해제/빌드 → 미완성 작업 확인 → 테스트 배포 및 최종 인수.
