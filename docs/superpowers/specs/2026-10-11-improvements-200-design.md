# 척척사장 홈페이지·앱 200개 전체 실행 설계

2026-10-11 · 범위 실행 승인: 사용자 “다 진행하셈”. 이 문서는 새 구조와 정책의 검토본이며, 200개 개발 완료 보고가 아니다.

## 목적과 성공 기준

사장님이 종이·단톡방·엑셀을 오가며 근무와 월급을 다시 맞추는 일을 줄인다. 직원은 본인 근무·급여의 근거·계약서·명세서를 직접 확인한다. 가입한 사람이 매장과 역할에 맞는 안내를 따라 첫 직원 연결→첫 근무표 공유→첫 출퇴근→첫 급여 검토까지 진행할 수 있어야 한다.

사용자가 요청한 홈페이지 100개와 앱 100개를 원본 ID로 추적한다. 이미 배포한 추가 HR 9개는 별도 완료 범위이며, 200개 중 겹치는 부분은 인수조건까지 대조한 뒤 증거를 연결한다. 매출·지출·순이익·재고·발주와 직원 추천 채용은 추가하지 않는다. 원본 APP-088·HOME-047에 남은 매출 관련 표현도 HR 비교로 수정했다.

완료는 네 단계로 구분한다. **구현**은 실제 화면·저장·다음 행동의 연결, **검증**은 서버 권한·합계·기간 경계·실패 복구·모바일 확인, **배포**는 운영 SHA와 공개 화면 확인, **관측**은 실제 고객 인터뷰·사례·사용 지표 결과다. 관측 자료가 없으면 개발을 완료해도 그 항목의 전체 완료를 주장하지 않는다.

## 확인한 현재 상태

- 앱 기준은 main `98087f6e1a48de8b9c7ad7773a31354f1733530e`. 기존 격리 체크아웃에 `improvements-200` 브랜치를 만들었다.
- `site/`가 실제 홈페이지다. `homepage/src/`는 별도 구형 경로이므로 이를 고치는 것만으로 공개 홈페이지가 바뀐다고 간주하지 않는다.
- 홈페이지 저장소 `skifighting-afk/chukchuksajang`의 배포 워크플로는 앱 저장소 main을 가져온다. 현재 홈페이지 작업 폴더에는 미커밋 체험·로고·모션 변경과 자산이 있다. 보존한 뒤 검토·이식하며, 앱의 최신 main을 통째로 이전 홈페이지 브랜치로 되돌리지 않는다.
- main의 `lib/plans.ts`에는 직원당 단가 2,900원·3,900원과 기존 지점 구간 계산이 함께 있다. 실제 결제 주문 경로는 기존 구간 계산을 사용하므로 가장 먼저 통합해야 한다.
- 시작 안내 숨김은 계정·매장 구분 없는 localStorage 키다. 매장·역할·다른 기기 간 복원을 보장하지 않는다.
- 자료 가져오기는 이름을 Map으로 변환한다. 동명이인의 앞 항목을 덮어 잘못 연결할 수 있다. APP-094의 기존 승인 설계에 따라 직원 ID 또는 직접 선택으로 해결하는 보호 작업을 먼저 진행한다.
- 기존 매뉴얼은 사진과 외부 HTTPS 영상 링크를 지원한다. 영상 직접 업로드·비공개 재생·자막을 제공한다고 표시하지 않는다.

## 접근 방식과 순서

독립된 앱을 새로 만드는 방식은 직원·권한·급여가 중복된다. 200개를 한 번에 대규모 커밋으로 바꾸면 실패 원인과 되돌릴 범위가 불명확해진다. **기존 React/TypeScript·Supabase/PostgreSQL 구조를 유지하고, 독립 검증 가능한 8개 묶음으로 순서대로 출시**한다. 데이터 오연결처럼 확인된 결함은 해당 묶음 순서보다 앞서 보호한다.

전체 항목·원본 실행 내용·인수조건·관련 기반 파일·현재 상태는 `척척사장-200개-실행대장.json`과 CSV/HTML에서 관리한다. 관련 파일 존재는 구현 완료 증거로 사용하지 않는다. 새로운 테이블·권한·결제 정책·외부 저장 비용에 영향을 주는 묶음은 이 설계의 검토 후 세부 실행 계획을 작성한다. 기존 승인 항목의 작은 오류 수정은 현재 승인과 직접 구현 방식을 유지한다.

**과금 인원 제안:** 청구 사업자의 재직 직원 중 활성 고용만 포함한다. 초대 대기·입사 준비·퇴사 완료·표시된 테스트 계정과 사장님 본인 계정은 제외한다. 동일한 인증 계정이 여러 매장에 연결되면 한 사람으로 집계하고, 연결 계정이 없는 직원은 직원 ID로 집계한다. 이름·전화번호가 같다는 이유로 합치지 않는다. 0명은 0원이며 포함·제외 목록, 집계 시점, 가격 버전을 주문 확인 화면에 표시한다. 유료 기간 중 인원 변경은 다음 청구에 반영하고, 신규 직원의 기능 접근을 막지 않는다. 기존 구독은 원래 가격 스냅샷을 보존하고 본인의 명시적 전환 전 임의 재청구하지 않는다. 플랜 전환·취소·환불은 기존 거래의 가격 스냅샷으로 산정하며 새 결제 약관을 확정하기 전 실제 청구를 바꾸지 않는다.

## C. 일간·월간 스케줄과 출퇴근

예정·실제 원본·정정 승인값·급여 반영 시간을 같은 축으로 보여 준다. 서버 판정 시각과 기기 시각은 분리하고 원본을 바꾸지 않는다. 지각 기준은 별도 설정이며 자동 급여 차감 규칙으로 해석하지 않는다. 미퇴근 안내는 확인·미루기를 제공하며 임의 퇴근 시간을 저장하지 않는다. QR·키오스크는 유효성·연결 상태·본인 확인·완료 후 초기화를 구분한다.

오프라인 요청은 계정·매장·직원·기기 범위와 고유 요청 ID에 묶는다. 로그아웃·계정 변경 후 타인에게 재전송하지 않는다. 재연결 시 실제 서버 확정 결과를 확인하고 미확정 상태를 성공으로 표시하지 않는다.

## E. 대타·휴가·승인과 직원 모바일

**대상:** APP-051~070.

요청→동료 수락→담당자 승인→근무표 반영을 같은 이력으로 보여 준다. 후보는 현재 매장·가능 시간·휴가·겹침·업무를 확인하고 제외 이유를 설명한다. 수락·승인 시 다시 검사한다. 공유 사유와 담당자 비공개 메모를 분리한다. 승인 전 전후 근무·시간·인건비 차이를 보여 주고 동시 수락·자기 승인·중복 승인을 서버에서 차단한다. 만료 요청은 더 승인할 수 없으며 확정 후 취소는 새 변경 흐름으로 보낸다.

직원 홈은 오늘 출퇴근·다음 근무·확인할 변경을 우선한다. 성공에는 본인·매장·서버 시각·다음 행동을 보여 준다. 급여 질문은 선택 항목·기간·계산 버전을 연결한다. 개인 정보 변경은 요청·대기·적용을 표시한다. 개인 달력에는 본인 일정만 포함하고 재발급·해지·갱신 정책을 안내한다. 지원 언어별 핵심 업무 전체와 큰 글씨·화면 읽기·키보드를 검증한다. 알림 시간·중요도·즉시 예외를 실제 전달 정책에 연결한다.

## F. 매뉴얼·교육·인수인계

**대상:** APP-071~080.

기존 매뉴얼·퀴즈·체크리스트와 배포된 HR 교육·담당 선배·숙련도를 연결한다. 복사한 틀은 검토 전 비공개이고, 제목·단계·공개 대상·버전·수정 요약·읽음·재확인·교육 완료를 분리한다. 입사 후 날짜가 지났다는 이유로 미완료 교육을 숨기지 않는다. 업무·매장·현재 교육을 기준으로 추천하고 전체 목록 접근을 제공한다.

직접 영상은 비공개 저장소에 보관하며 현재 권한을 검사한 짧은 유효 기간의 업로드·재생 권한으로 접근한다. 형식·크기·길이·썸네일·교체·자막·실패 재시도 정책을 세부 계획에서 고정한다. 큰 파일을 일반 JSON API에 넣지 않는다. 업로드 공급자 설정과 비용이 없는 상태에서는 외부 링크 지원만 정확히 표시한다. 미디어 실패가 작성 중 체크리스트를 지우지 않게 한다.

인수인계는 매장·근무·담당자·사진·기한·처리 상태를 연결하고 미해결 건을 다음 담당에게 이어 준다. 도우미 답변에는 접근 가능한 매뉴얼의 제목·단계·버전 근거만 붙인다. 근거가 없으면 담당자에게 연결하며 절차를 지어내지 않는다.

## G. 여러 매장과 위임 관리자

**대상:** APP-081~090.

전체/선택 매장·기간을 항상 표시하고 목록·합계·편집 범위를 일치시킨다. 오늘 예상 인건비는 시급 누적과 월급 배분, 자료 부족·미정 비용·갱신 시각을 설명한다. 미출근·빈 근무·미승인·정산 예외는 사건별로 중복 없이 집계한다. 권한 묶음은 기존 서버 권한을 제안하는 도구이며 화면을 숨기는 것만으로 접근을 허용하지 않는다.

기간 위임은 시작·만료·회수 직후 열린 화면과 새 요청 모두에 적용한다. 다중 매장 직원은 인증된 사람과 지점별 고용 조건을 구분하며 이름·전화만으로 합치지 않는다. 상담·면담·급여의 개인 권한을 넓히지 않는다. 도우미는 조회와 실행을 구분하고 대상·범위·변경·비용을 미리 보여 준다. 실행은 서버의 현재 권한·버전·중복 방지·확정 상태를 통과해야 한다.

## H. 데이터 보호·측정·운영

**대상:** HOME-081·088~100, APP-094~100.

자료 가져오기는 직원 ID·매장·기간·명시적 연결을 사용한다. 동명이인·미매칭은 자동 선택하지 않고 원본 행과 후보를 보여 준다. 가져오기 묶음은 반영 전 변경 요약·제외·충돌을 확인하고 되돌릴 때 이후 수정·확정된 기록을 조용히 삭제하지 않는다. 동시 수정은 버전 충돌과 최신 변경을 표시하며 작성 내용을 보존한다.

안전한 문의 진단은 버전·오류 번호·현재 화면·처리 상태만 준비하고 사용자가 내용을 확인한 뒤 제출한다. 계좌·급여·인증 정보·상담 본문은 포함하지 않는다. 분석은 허용된 이벤트 이름·역할·매장 범위·CTA 위치·기능 ID·오류 종류·시간 구간만 수집한다. 자유 입력·직원 이름·급여·계좌·비밀번호·HR 비공개 본문은 거부한다. 데이터 최소화·사용 목적·동의와 보관은 현재 처리방침에 맞춰 검토한다.

전환은 방문→체험/가입 클릭→가입 완료→첫 직원→첫 근무→첫 급여→문서 전달→유료 선택으로 구분한다. 중복 이벤트를 제거하고 방문 수·오류·중도 이탈을 분리한다. 실제 전환율·성능 p75·A/B 승자·고객 사례는 실사용 표본과 자료로만 판정한다. 고객에게 메시지를 보내거나 인터뷰를 예약하는 일은 별도 명시적 지시 없이 수행하지 않는다.

## 배포·검증과 완료 기록

1. 깨끗한 격리 브랜치에서 묶음별로 테스트→구현→전체 검사→독립 최종 검토→PR을 진행한다. 기존 미완성 변경은 백업하고 필요한 부분만 검토해 이식한다.
2. 합성 PostgreSQL은 `127.0.0.1:55432/chuck_test`를 사용한다. 실제 고객 자료로 시험 입력·알림·급여·계약을 만들지 않는다.
3. 서버 권한은 사장님·공동관리자·기간 위임·직원·퇴사자·미연결 계정과 다른 사업자·지점·문서 조합으로 검사한다.
4. 실패·409 충돌·느린 연결·중복 클릭·응답 유실·계정 전환과 키보드·모바일을 포함한다. 각 새 상태 전이가 의미 있는 회귀로 보호되는지 확인한다.
5. 자동 배포 승인은 유지한다. 필수 CI가 통과한 정확한 커밋만 병합하고 앱·홈페이지 각각의 운영 SHA/빌드·공개 화면을 확인한다.
6. 실행대장에는 커밋·검증 명령·실제 결과·운영 확인을 기록한다. 원본 제안이 실험·자료 작업이면 개발 완료와 최종 관측 완료를 별도로 기록한다.
